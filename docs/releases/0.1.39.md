# Parker 0.1.39 Release Notes

Status: Draft

`0.1.39` fixes name lookups that broke on non-ASCII capital letters and removes N+1 queries from the person and series issue views.

## Added

- None yet.

## Changed

- None yet.

## Fixed

- Fixed metadata scans stopping partway through a library when a tag name starting with a non-ASCII capital letter, such as `Île-de-France`, already existed. Tag lookups compared Python `casefold()` against SQLite's ASCII-only `lower()`, missed the existing row, and hit the `ux_*_name_lower` unique index. That ended the metadata writer and skipped the rest of the library. Lookups now lower-case both sides in SQLite so they match the index.
- Fixed library create/rename and admin user create returning a server error instead of "already exists" when the name or username contained a non-ASCII capital letter, such as `Île-de-France` or `Élise`, and was already taken.
- Fixed N+1 queries in the person and series issue views: smart-cover selection for a person's role series is now batched instead of resolving one cover per series, and the series issues query reuses its Volume join so serialization no longer lazy-loads a volume per issue. Cover ranking behavior is unchanged.
- Fixed scans being recorded as `completed` with `imported: 0` when the metadata writer crashed partway through a library. The scan job is now marked `failed` with the writer's error, keeps the counts for comics committed before the crash, no longer advances the library's last-scanned time, and stops extracting metadata once the writer has died instead of finishing the whole library first. Thumbnail and cleanup jobs are still queued so comics committed before the failure get their thumbnails.
