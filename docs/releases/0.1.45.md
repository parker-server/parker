# Parker 0.1.45 Release Notes

Status: Draft

## Added

- Added background job lanes. Each lane has its own worker thread, so different kinds of work can run side by side. Library jobs (scan, thumbnail, cleanup, metadata rehydrate) stay in one lane and still run one at a time in the same priority order.
- Added an enrichment lane for critic review lookups. A lookup never waits behind a library scan, and scans never wait behind lookups. Lookups are spaced at least 3 seconds apart across the whole server, which keeps traffic to ComicBookRoundup low.
- Added review lookups to the admin Job History page:
  - a Review lookup badge, and the issue shown in the Target column
  - a details panel with the result, reviews stored, match confidence, provider, issue, and source link
  - a Show review lookups toggle in Recent History. Lookups are frequent, so they are hidden by default; the Active Queue always shows them.
- Added generic target columns (`target_type`, `target_id`, `payload_json`) to the job table, and a database rule that allows only one active review lookup per comic (migration `b8e2f4a6c1d3`).
- Added automatic database compaction at Docker startup. After migrations run and before the server starts, Parker checks how much of the database file is unused. If it's at least a quarter of the file and at least 50 MB (for example after a large deletion or a migration that removes data), it runs SQLite `VACUUM` to give that space back to the disk. Otherwise the check takes milliseconds and does nothing. If the disk doesn't have about twice the size of the compacted database free, or `VACUUM` fails, Parker logs a warning, starts normally, and tries again on the next start.
- Added a cover audit script (`python -m app.services.cover_audit`) for server admins. It reads each archive's file list without changing anything and writes `storage/cover_audit.csv`, listing archives whose cover pick deserves a manual look: the cover isn't the first page by plain filename order, more than one page looks like a cover, the cover sits in a tiny folder apart from the rest of the pages, or the archive has no pages or can't be opened. `--snapshot` saves every archive's current cover, and `--compare` writes `storage/cover_changes.csv` listing each archive whose cover changed since that snapshot, so you can check what a sorting change moved before regenerating thumbnails.
- Added a contact sheet to the cover audit (`--contact-sheet storage/cover_audit.csv`). It builds `storage/cover_audit_sheet/index.html` from a finished report without rerunning the audit, showing each flagged archive's chosen cover next to the pages it might have picked instead, with the most likely wrong picks first. You can filter by flag, tick wrong covers (remembered in the browser), and copy the ticked archives as a list.
- Added a page-list export to the cover audit. `--save-pages storage/pages.jsonl.gz` saves every archive's file list (filenames only, about 110 bytes per archive), and `--replay` runs the audit on those saved lists without opening archives, so cover sorting changes can be checked against a whole library on another machine in seconds.
- The cover audit's contact sheet can also be built from a `cover_changes.csv` (`--contact-sheet storage/cover_changes.csv`, written to `storage/cover_changes_sheet/`). Each card shows the new cover next to the previous one, so a cover sorting change can be checked by eye before thumbnails are regenerated.

## Changed

- Viewing an issue with external critic reviews enabled now queues the lookup in the persisted job queue, instead of running it in the web worker that served the page. Repeated views of the same issue don't queue duplicate lookups, even across app workers, and a lookup lost to a restart is retried the next time the issue is viewed.
- Review lookups never hold a database write open while waiting on ComicBookRoundup. Each of their writes lasts milliseconds, so they don't hold up the scan's metadata writer.
- The Job History page's Library column is now called Target. It shows the issue for review lookups and the library for everything else. Queue positions are numbered per lane, since each lane has its own worker.
- The scanning indicator only reflects library jobs, so a running review lookup is never shown as a scan.
- A review lookup interrupted by a server restart is now marked "External review lookup interrupted by server restart" instead of "Scan interrupted by server restart".
- Global cleanup also removes cached critic reviews whose comic no longer exists. The count is included in the cleanup job's summary.
- Scans no longer keep a full copy of each comic's `ComicInfo.xml` in the database. Nothing read it, and the XML is still inside each archive. Migration `c5f1a9d3e7b2` removes the copy from existing comics. The parsed fields that metadata rehydrate uses (reading lists, collections, story arcs) are kept. On a test library this cut the stored metadata per comic by about 73%.
- Comic queries no longer load each comic's stored metadata unless they need it. Only metadata rehydrate reads it.
- The startup compaction shrinks the database right after this migration, so the first start after upgrading can take a little longer on large libraries. Nothing needs to be run by hand.
- The search index (`comics_fts`) now stores only its word index, not a copy of each comic's title, series name, and summary. Search only uses it to find matching comic IDs, so results are unchanged. Migration `f2c7a9e4b1d6` rebuilds it this way, which saves about 55 MB on an 80,000-comic library. The freed space is reused for new data, or given back to the disk by startup compaction when enough is unused. This needs SQLite 3.43 or newer (the Docker image has 3.46.1). On older SQLite the migration keeps the stored copy, so search still works.
- Cover and page sorting rules, tuned against the cover audit of a 73,868-comic library and 200 hand-checked wrong covers:
  - "scan" is no longer a cover word. In that library every file it promoted was a scanner tag (`scan.jpg`, `Zombie Golfer Scan 09.jpg`, `zzztitansfan scan.jpg`).
  - A leading `_` now marks a page to sort first, as a leading `~` already did (`_IMG.jpg`, `_hawkworld book 01 - 00 ocd horus.jpg`).
  - Cover, back cover and inside cover words are read from the file name only, not the folders around it. A folder named `Fathom [Comico] 1 0f 3` had marked every page in it as a cover.
  - Wraparound covers that name both sides (`00 fc+bc`, `00_FC-BC`, `00fc29bc`) are ordinary pages: no longer sent to the back as back covers, and no longer chosen over a separate front cover.
  - The reader's page order cache version is now 9, so open readers pick up the new order. Existing cover thumbnails change only when regenerated.

## Fixed

- Fixed a critic review lookup whose final save failed (for example, on a database lock timeout) leaving the lookup stuck as pending. The failure is now recorded and the lookup is retried after the normal failure window.
- Fixed cached critic reviews being left behind when a comic was deleted. Because a deleted comic's ID can be reused, a newly imported comic could show the deleted comic's reviews. Deleting a comic now deletes its cached reviews.
- Fixed text search missing comics added or changed after upgrading to library roots. On SQLite, later migrations that changed the `comics` table (`d4a1f6e8b3c2`, `7e3ba96ed6dc`, `9def8df8ed7c`) rebuilt it, which silently dropped the three triggers that keep the search index (`comics_fts`) up to date. New comics were never indexed, and edited titles or summaries kept their old text. Migration `e8b4d2a6f1c9` puts the triggers back and rebuilds the index from every comic, so nothing needs to be rescanned. Migration `f2c7a9e4b1d6` then rebuilds it again as a word-only index that stores no copy of the text (see Changed).
- Fixed `alembic check` and `alembic revision --autogenerate` reporting changes that shouldn't be made. Autogenerate wanted to drop the search index tables, which migrations create directly and which have no model, so `alembic/env.py` now leaves `comics_fts*` tables out of the comparison. Four model columns (`comics.is_dirty`, `users.share_progress_enabled`, `users.allow_unknown_age_ratings`, `users.monthly_reading_goal`) now say `nullable=False`, matching the database, and the model no longer asks for an extra index on `activity_log.id`, which the migrations never created and the primary key already covers. No database changes.
- Fixed a scanner's credit page being picked as the cover when an archive keeps its pages inside a folder. Pages whose names start with `z` (such as `zzz A Comixbear Scan.jpg`) are meant to sort last, but the check looked at the start of the whole path, so it missed them inside a folder, and the word "Scan" then marked the page as a cover. The check now looks at the file name only. The reader's page cache version is bumped so open readers use the new order. Covers already generated stay as they are until their thumbnails are regenerated.
- Fixed wrong covers found by the cover audit (363 of 73,868 comics in the tested library):
  - Scanner tags wrapped in `xx` (`XX-Empire-Meganubis-XX.JPG`, `Xx-MegaXMan-xX.JPG`) are sent to the end. Because `-` sorts after letters, `X-Man_31_0000.jpg` used to sort after the tag.
  - The main `000` cover now wins over a lettered variant with the same start even when extra text follows the letter (`Batman 678-000b (Tony Daniel variant).jpg`, `action388-00a horse murals.jpg`, `Elektra_#1_pg00a_anthony.jpg`). Before, this only worked when everything after the letter matched.
  - Tags glued to their `z` (`zzmm.jpg`, `zzZdizzylocke.jpg`, camelCase `zWraithOfSpectre02_00a.jpg`) are sent to the end. Names like `Zatanna 01.jpg` are unaffected.
  - A back cover glued to its page number (`p00bc`) is recognised, and cover words joined by underscores (`00a_inside_front_cover`, `66_back_cover`) count like words joined by spaces.
  - `fc` glued to a short page number (`scan-01fc_Bullseye.jpg`, `Power Factor_001-01FC.jpg`) is a cover word.
- Fixed macOS resource fork files (`._page.jpg`, often under `__MACOSX/`) being treated as pages. They are not images, so they showed as broken pages and could be picked as the cover.
