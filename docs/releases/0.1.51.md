# Parker 0.1.51 Release Notes

Status: Draft

## Added

## Changed

- System setting keys are now declared once, in `app/core/setting_keys.py`. `SettingsService.DEFAULTS` and every part of the app that reads a setting use these constants instead of typing the key out, replacing a mix of string keys and per-feature constants such as `NOTIFICATIONS_ENABLED_SETTING` and `DOWNLOADS_ENABLED_SETTING`. The scheduler and the settings API build and recognise task interval keys through `setting_keys.task_interval()` and `setting_keys.is_task_interval()`. Nothing changes for readers or admins: every key keeps its name and stored value.

## Fixed

## Validation

- New `tests/core/test_setting_keys.py` checks that every default setting has a constant and every constant has a default, that constant names follow their keys, that each scheduled task has an interval setting, and that every key a template reads exists. Each check was confirmed to fail on purpose: a misspelled constant value, a misnamed constant and a misspelled template key.
- Ran the full suite: `1636 passed` via `.\.venv\Scripts\python.exe -m pytest -q`.
