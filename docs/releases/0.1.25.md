# Parker 0.1.25 Release Notes

Status: Draft

`0.1.25` is a storage-identity and library-root release. Parker now identifies physical comic files by `(library_root_id, relative_path)` instead of cached absolute paths, ships safe library-root relocation, and introduces the root lifecycle controls needed for multi-root libraries.

## Added

- Added the `library_roots` table and `LibraryRoot` model. `Library` remains the logical library, while `LibraryRoot` represents one configured filesystem root.
- Added durable comic root identity with `Comic.library_root_id` and `Comic.relative_path`, plus a unique index on `(library_root_id, relative_path)`.
- Added `Comic.absolute_path`, which reconstructs the current filesystem path from the comic's assigned root plus its relative path.
- Added root-aware path helpers in `app/core/path_utils.py` for OS-independent relative-path calculation, absolute path reconstruction, and overlap detection.
- Added Alembic migrations for the full root-identity transition:
  - `d4a1f6e8b3c2` creates `library_roots`, backfills one root per library, and assigns comic root/relative-path values.
  - `71464b56eb8a` retries the root-identity backfill with corrected segment-based matching.
  - `7e3ba96ed6dc` finalizes the invariant by retrying matching, deleting unresolved comics, making root identity non-null, and enforcing uniqueness.
  - `9def8df8ed7c` drops the legacy `Comic.file_path` and `Library.path` columns.
- Added admin APIs for library-root lifecycle management: list roots, add roots, enable/disable roots, remove roots, and delete comic records tied to a removed root when explicitly requested.
- Added a non-mutating relocation preview service/API that reports matched, missing, and new archive counts before any root path is changed.
- Added a relocation confirmation service/API that recomputes the preview, updates the selected `LibraryRoot.path`, preserves matched comic IDs, refreshes file watches, and returns scan recommendation details without queuing a scan automatically.
- Added the admin library UI for root management and relocation, including path browsing, preview counts, sample matched/missing/new files, confirmation, scan recommendation messaging, and an explicit post-relocation force-scan action.
- Added a `min_value` setting metadata field and applied it to `scanning.batch_window`.
- Added a Wiki link and build commit display to the admin About page, including GitHub Actions build metadata for published Docker images.
- Added five new static login cover backgrounds: Wolverine #27, Batman #423, Daredevil #168, New Mutants #87, and New Teen Titans #1.

## Changed

- Upgrade note: if a library folder was manually moved outside Parker and has not been rescanned since, scan it before upgrading. During upgrade, comics that cannot be matched to any configured root are deleted and can be re-imported on a future scan, but their reading progress, bookmarks, ratings, and list membership will not carry over.
- Upgrade note: if libraries live on network or removable storage, make sure those paths are reachable before upgrading. The migration cannot distinguish an unavailable mount from a genuinely missing path.
- `Library.path` and `Comic.file_path` are no longer compatibility fields. All path-aware code now works through `LibraryRoot.path`, `Comic.library_root_id`, and `Comic.relative_path`.
- Scanner discovery, scanner cleanup, metadata worker handoff, metadata writing, sidecar lookup, thumbnailing, maintenance cleanup, watcher registration, startup diagnostics, OPDS, the reader, the comics API, admin reports, and Kavita migration now reconstruct or compare paths from root-relative identity.
- Scans and watcher registration now understand multiple active roots per library, while scan jobs remain library-scoped.
- Missing-file cleanup now fails conservatively when an active root in scope is unreachable, instead of pruning records while storage may simply be offline.
- Sidecar reconciliation now stops at the physical root that owns the comic being processed.
- Admin library responses include root payloads, active-root counts, and per-root comic counts.
- Creating a library now creates its initial root in the same transaction as the library row.
- Generic library path edits remain blocked; admins are directed to the dedicated Relocate flow instead.
- Library names are trimmed, required on create/update, and checked for duplicates case-insensitively.
- The scan batch window setting now has a 60-second minimum to reduce watcher-triggered scan churn around filesystem-heavy operations.
- The library relocation and root lifecycle flows block while scan-pipeline jobs for the library are queued or running.
- Disabling the last active root now prompts admins to confirm the library will stop scanning, watching, importing, and reconciling files while existing comics remain visible.
- The Add Library modal now clarifies that additional roots are managed after creation from the Roots link.
- The relocation flow blocks confirmation when a library already has comics and none match at the proposed new root.
- The relocation preview modal caps displayed matched, missing, and new file samples so very large libraries do not blow up the dialog.
- Publisher and imprint logo rendering now uses a shared circular metadata badge style.
- Series and volume synopsis clamping now uses the same length rule as the `Read More` link, preventing clipped text without an expansion control.
- The login page now focuses the username field on load.
- README and planning docs were updated to reflect implemented library relocation and multi-root root-lifecycle support, and completed relocation/multi-root TODO items were removed.

## Fixed

- Fixed N+1 query patterns in OPDS root feeds, home rails, and admin reports.
- Fixed remaining N+1 query issues in home/report surfaces after the first pass.
- Fixed root-relative matching so it compares path segments instead of relying on the current OS path separator or normalization rules.
- Fixed matching for libraries configured at filesystem roots such as `/` or `C:\`.
- Fixed reconstructed path display so Windows paths are normalized to Parker's preferred `/` separator style.
- Fixed unresolved-comic cleanup in the finalize migration so dependent rows are explicitly removed before raw SQL comic deletes. This covers bookmarks, reading progress, ratings, activity logs, collections, reading lists, pull lists, credits, and tag associations.
- Fixed large unresolved-comic migration cleanup by batching dependent deletes and final comic deletes below SQLite's bound-parameter limit.
- Fixed ORM-level comic deletion cascades for `UserComicRating` and `ActivityLog`, preventing scanner and maintenance deletes from orphaning those rows.
- Fixed a library creation failure mode where the library row could commit without its matching root row.
- Fixed relocation overlap validation so proposed paths cannot overlap the current root, another root in the same library, or a root in another library.
- Fixed relocation preview/confirm behavior while active or queued scan, thumbnail, or cleanup jobs exist for the same library.
- Fixed the relocation scan-recommendation follow-up dialog so it appears when a scan is recommended.
- Fixed the admin diagnostics Configured Libraries section so it renders every configured root with per-root active and path status.
- Fixed the relocation modal's duplicated close affordance and scoped modal buttons to the intended dialog.
- Fixed blank library names and case-only duplicate library names such as `Marvel` vs `marvel`.
- Fixed the series/volume synopsis ellipsis mismatch where summaries could show an ellipsis without a visible `Read More` control.
- Fixed publisher and imprint badge rendering so differently shaped logos look more uniform, without adding artificial white borders to opaque logos like Marvel.
- Fixed the login page autofocus gap for the username field.
- Fixed test leakage from local single-volume redirect settings by pinning that setting inside the browser test server.
- Tightened parallel scanning and thumbnail error handling to avoid under-reporting or double-reporting failures.
- Replaced remaining print-style service diagnostics in touched paths with logger calls and reduced noisy duplicate output.
