# Parker 0.1.25 Release Notes

Status: Release Candidate

`0.1.25` is Parker's library roots and safe relocation release. It moves Parker toward root-based library storage, adds admin workflows for relocating library roots, and includes several admin, diagnostics, and UI polish improvements.

## Added

- Added Library Roots management for admins. Existing libraries now have a root record behind the scenes, and roots can be viewed, added, enabled, disabled, or removed from the Admin Libraries page.
- Added safe library relocation from Admin > Libraries. Admins can browse for a new folder, preview what Parker will match before anything changes, then confirm the relocation when the preview looks right.
- Added relocation preview details for matched files, missing files, and new archive files, with capped samples so large libraries do not overwhelm the dialog.
- Added root-aware storage identity so Parker can preserve comic records, reading progress, bookmarks, ratings, and list membership when a library root is relocated safely.
- Added diagnostics support for library roots, including per-root path and active status in the Configured Libraries section.
- Added a Wiki button and current build commit display to the About page. GitHub-built Docker images now include commit metadata for easier support identification.
- Added new static login cover backgrounds for Wolverine #27, Batman #423, Daredevil #168, New Mutants #87, and New Teen Titans #1.
- Added additional publisher/logo coverage, including Black Bull.

## Changed

- Upgrade note: if a library folder was manually moved outside Parker and has not been rescanned since, scan it before upgrading. Comics that cannot be matched to a configured root during the upgrade can be re-imported later, but their reading progress, bookmarks, ratings, and list membership will not carry over.
- Upgrade note: if libraries live on network or removable storage, make sure those paths are reachable before upgrading. Parker cannot distinguish an unavailable mount from genuinely missing files during the root-identity migration.
- Library scanning, watching, cleanup, reading, OPDS feeds, thumbnails, reports, sidecar handling, and Kavita migration now use root-relative file identity instead of stored absolute paths.
- Scans and watches now process all active roots for a library, while scan jobs remain library-scoped.
- Missing-file cleanup now stops conservatively when an active root is unreachable, reducing the risk of removing records while storage is offline.
- Creating a library now creates its first active root automatically. The Add Library modal clarifies that additional roots can be managed after creation from the Roots link.
- Existing library paths are changed through the dedicated Relocate flow instead of direct library edits.
- Library relocation does not queue scans automatically. When a scan is recommended, admins now get an explicit follow-up prompt.
- Disabling the last active root now asks for confirmation and explains that existing comics remain visible while scans, watches, imports, and missing-file reconciliation stop until a root is re-enabled.
- The scan batch window setting now has a 60-second minimum to reduce watcher-triggered scan churn around filesystem-heavy operations.
- Publisher and imprint logos now render in a shared circular badge style for a more consistent look.

## Fixed

- Fixed root-relative path matching across Windows/Linux separators and libraries configured at filesystem roots.
- Fixed reconstructed Windows path display to use Parker's preferred `/` separator style.
- Fixed library relocation validation so proposed paths cannot overlap the current root, another root in the same library, or a root in another library.
- Fixed relocation confirmation being allowed when an existing library had zero matching files at the proposed new root.
- Fixed relocation actions while scan, thumbnail, or cleanup jobs are queued or running for that library.
- Fixed the relocation scan-recommendation dialog so it appears after relocation when needed.
- Fixed blank library names and case-only duplicate library names such as `Marvel` and `marvel`.
- Fixed delete/cascade gaps that could orphan ratings, activity logs, bookmarks, progress, list membership, or other dependent rows when comic records are removed by scanner, maintenance, or migration paths.
- Fixed a library creation failure mode where the library row could be saved without its first root.
- Fixed N+1 query patterns in OPDS, home, and admin report surfaces.
- Fixed series and volume synopsis expansion so ellipses and Read More links follow the same rule.
- Fixed the login page so the username field receives focus on load.
- Fixed scan and thumbnail failure reporting gaps that could under-report or double-report errors.
