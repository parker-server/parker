# Parker 0.1.27 Release Notes

Status: In Progress

`0.1.27` is currently focused on small user-facing polish following the CBL reading-list release.

## Added

- Added a `Cycle Static Covers` login background option that cycles through Parker's bundled iconic cover backgrounds using the existing login-page crossfade behavior.
- Added missing bundled login cover options for Batman #227, Spider-Man #1, and Superman #75.
- Added new static login cover options for Brave and the Bold #28, Detective Comics #359, Teenage Mutant Ninja Turtles #1, Thor #337, and Wonder Woman #1 (Vol. 2).
- Added Git commit hash metadata to the Diagnostics support snapshot JSON so edge builds can be identified even when the displayed app version still reflects the last stable release.
- Added series recommendation rails to single-volume detail pages so admins who enable direct single-volume redirects still see the discovery rails normally found on the series page.
- Added comic counts to My Stacks cards, backed by a SQL aggregate so the index does not walk stack items per card.
- Added focused API/page and Playwright coverage for the new static-cover cycling login mode.
- Added coverage to keep bundled login cover assets and selectable static-cover options in sync.

## Changed

- Static login cover options are now ordered alphabetically by display name so admins can find covers more easily.
- Admin Settings now groups System settings into Scheduled Tasks, Metadata Processing, and Thumbnail Processing sections so related controls stay together.
- Admin Settings now groups Appearance settings into Login Page, Library Presentation, and Browsing Behavior sections.
- Diagnostics now labels the configured-library sample count and keeps that list scroll-contained so large library sets do not make the page unwieldy.
- Diagnostics card relocated near the end of the admin dashboard just before 'About' card.
- Login static-cover defaults now use the bundled `.webp` asset names consistently.
- Existing stale `ui.login_static_cover` values that point at invalid static cover filenames are normalized back to the default bundled `.webp` cover during settings initialization.
- Recently Added Series, Recently Updated Series, and pinned-library recently updated rails now show the smart cover from the volume that was actually added or updated instead of always falling back to the series-level cover.

## Fixed

- Fixed the login static-cover fallback still pointing at the old `amazing-fantasy-15.jpg` filename even though the bundled login covers are stored as `.webp`.
