# Parker 0.1.38 Release Notes

Status: Draft

`0.1.38` is a focused patch release for archive cover ordering when scanner or uploader naming patterns put extras ahead of the intended first page.

## Added

- Added Eagle Comics, Eternity publisher logos.
- Added client-side pagination and name/path filtering to the admin Libraries page, including matches across all configured library roots.

## Changed

- Bumped the archive page-order cache version so readers refresh cached page ordering after the latest cover detection rule change.
- Replaced several hand-built API response payloads with explicit Pydantic response schemas for comic, series, volume, timeline, collection, reading list, pull list, and cover mural endpoints.

## Fixed

- Fixed archive cover selection when a scanner or uploader uses a leading `~` prefix to force issue pages ahead of unprefixed extras, such as `~max0017.jpg` before `Santa-DCP.jpg`.
- Fixed archive cover selection when an appended page-number variant exists beside the base issue image, such as `Nemesis 07.jpg` before `Nemesis 07_0002.jpg`.
- Fixed scan pipeline ordering under multi-worker Uvicorn deployments so only the process that owns the manager lock starts the ScanManager queue worker, preventing cleanup jobs from running concurrently with thumbnail jobs that should precede them.

## Validation

- Verified archive cover regression coverage and reader API cache-key behavior after the leading-tilde and appended page-number ordering fixes: `37 passed` via `.\.venv\Scripts\python.exe -m pytest tests\services\test_archive.py tests\api\test_reader.py -q`.
- Verified admin Libraries pagination and filtering with browser coverage: `1 passed` via `.\.venv\Scripts\python.exe -m pytest tests\browser\test_admin_library_relocation.py::test_admin_libraries_client_pagination_and_filter`.
- Verified ScanManager lifecycle, scheduler queue integration, and job queue API behavior after moving ScanManager startup behind the manager lock: `53 passed` via `.\.venv\Scripts\python.exe -m pytest tests\services\test_scan_manager.py tests\services\test_scheduler_service.py tests\api\test_jobs.py -q`.
- Verified the API response-schema refactors across comic, series, volume, timeline, collection, reading list, pull list, and cover mural coverage: `127 passed` across focused `tests\api` pytest runs.
- Manually verified a two-worker Uvicorn startup where only the lock-owning process started Watcher, ScanManager, and Scheduler, then confirmed a library scan ran scan, thumbnail, and cleanup jobs sequentially.
- The sandboxed Python validation process failed to start with the known `encodings` import error, so validation used the repository-prescribed elevated retry.
