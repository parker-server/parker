# Parker 0.1.50 Release Notes

Status: Draft

## Added

- Problem reports. Readers can report a problem with a comic they can open (bad scan, missing pages, pages out of order, won't open, wrong metadata, wrong comic, or other) from a warning icon in the reader toolbar, which fills in the current page, or on the comic page. Reporting the same kind of problem again updates the open report, and readers can withdraw open reports and follow them on a My Reports page (`/user/problems`), linked from a card on the dashboard.
- Admin Problems page (`/admin/problems`), with a card and open count on the admin dashboard. Reports are grouped by comic and category, with each reporter's details, and can be resolved, dismissed or reopened one group at a time or as a selection, with an optional note for the reporter. **Open at page** opens the reader in incognito at the reported page.
- Problem report notifications: admins get `admin_problem_new` when a report is created (one grouped notification on a busy day), and reporters get `problem_resolved` when their report is resolved or dismissed, with the admin's note.
- When a scan picks up a changed file for a comic with open reports, the reports are flagged **File updated since report** (with a filter for them). Parker never closes a report on its own. Reports on deleted comics are kept, labelled with the series, number and path they had, and shown as **Comic removed**. Reports from a deleted account are kept too and shown as from **Deleted user**.
- **Enable Problem Reports** setting under Settings > Features (on by default) and an **Allow reporting problems** permission per user. Admins can always report, and the admin page stays available when the setting is off.

## Changed

- The library access and age-rating check used by bookmarks moved to a shared `ensure_comic_access()` helper in `app/core/comic_helpers.py`, which problem reports also use.
- A notification kind can now belong to a feature setting. While that feature is off, its switch is hidden from notification preferences and nothing of that kind is sent; a user's saved choice is kept for when it is turned back on. The two problem report kinds use `features.problem_reports_enabled`.

- Page routes and the series, volume, comic, reading progress and reader APIs now run as plain functions in the server's thread pool instead of on its event loop, so a slow database call in one of them no longer stalls every other request in that worker. This is the first batch of the conversion planned in `docs/async-route-conversion-scope.md`; 65 routes are converted.

## Fixed

- The reader now sends one reading progress save at a time. Turning pages quickly could send overlapping saves that counted some pages twice in reading stats and Year in Review, or saved progress a page behind where the reader stopped. Page turns made while a save is running now go out as one save of the latest page, and a save still waiting is sent when the reader is closed.
- Fixed a long-standing login bug, present since the 2-hour idle timeout arrived in 0.1.23, where signing in after being away for a while sometimes sent you straight back to the login page. The home page would flash with nothing loaded, then the login page came back, and signing in a second time worked. The login page never reset the idle clock. If your last session ended without a normal logout (for example, your session cookie simply expired), the old activity time was still stored, so the first page after login treated the new session as idle and cleared it. Signing in now starts the idle clock fresh.
- Fixed a browser test that left an extra comic in the shared test volume, which made the two cover browser lazy-loading tests fail whenever they ran after it.
