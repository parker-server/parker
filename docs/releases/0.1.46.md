# Parker 0.1.46 Release Notes

Status: Draft

## Added

- Added a Change Cover option for admins on each comic's page, for covers the filename rules can't get right (wraparound covers, one-off archives). It shows the first 12 pages of the archive to pick from, takes an uploaded JPEG, PNG or WebP image (up to 10MB), and can reset to the automatic pick. The dialog shows which one is in use, and the thumbnail and cover colors update straight away.
- Added two comic columns for the manual cover: `cover_override_page` (the chosen page's filename in the archive, so cover sorting changes can't move it) and `cover_override_image` (the uploaded file, saved in `storage/cover_overrides/`) (migration `a7d3e9f2c4b1`).
- Added admin-only cover endpoints: `GET /api/comics/{id}/cover` lists the candidate pages and the active choice (previews use the reader's page endpoint), `PUT` sets a page by filename, `POST /api/comics/{id}/cover/upload` uploads an image, and `DELETE` resets to automatic. Each change regenerates that comic's thumbnail right away; if that fails the comic is marked for the next thumbnail task.
- Global cleanup deletes uploaded cover images whose comic no longer exists, for example after its file was moved, renamed or deleted. The count is included in the cleanup job's summary (`orphaned_cover_overrides_deleted`). Per-library cleanup leaves them alone.
- Added a **Thumbnails** button to each library in Admin > Libraries, next to **Force**. It rebuilds the thumbnail and cover colors for every comic in that one library without rescanning its files, so one library's covers can be redone without a force rescan, and without touching other libraries. The confirmation names the library and how many comics it holds. Behind it is a new admin-only endpoint, `POST /api/libraries/{id}/thumbnails`.
- Added an **Issues / Series** switch to Advanced Search. Series shows one card per series that has matching issues, with how many of its issues matched, so a search like "Series contains absolute" lists each series once instead of every issue. Issues is still the default. Sorting works per series (Date Added and Date Updated use the newest matching issue, Release Year the earliest, ratings the average); Issue Title and Page Count are unavailable in Series mode. Saved searches remember the choice, and searches saved before this open as Issues. The Featured Rail editor doesn't show the switch.
- Added `POST /api/comics/search/series`. It takes the same request as `/api/comics/search`, with the same library and age-rating restrictions, and returns series with a `match_count`, counted and paged by series. Search requests have a new `result_mode` field (`issues` or `series`) that is saved with the search; the issue search ignores it.
- Added a **See all matching series** link under the Series group in navbar quick search. It opens Advanced Search in Series mode with one "Series contains" rule per typed word, so it matches words in any order like quick search does.

## Changed

- Thumbnail generation now uses a comic's manual cover when it has one: the uploaded image first, then the chosen page, then the automatic pick. A chosen page that is no longer in the archive (for example after the file was replaced) falls back to the automatic pick without an error. Reader page order is unchanged.
- A manual cover survives rescans of the same file, and thumbnails regenerated after a rescan still use it. It is lost when the comic's file is moved, renamed or deleted, like reading progress.
- Cover Mural export uses a comic's manual cover too.
- Navbar quick search now lists the closest matches first in every group: names that start with what was typed, then names containing the exact phrase, then names that just contain all the words, with shorter names first. Before, each group showed its first 5 matches in no particular order.
- The **Advanced Search for "…"** link at the bottom of navbar quick search now opens Advanced Search with one "Series contains" rule per typed word instead of one rule for the whole phrase, so it finds the same series quick search does, whatever the word order or punctuation. A one-word search opens exactly as before.
- The Advanced Search page's address now follows the current search (rules, match, sort, limit, Issues or Series, and library), updated in place on each search without adding history entries. Pressing Back after opening a result reruns the search instead of showing a blank page, and the address can be bookmarked or shared. A search too long for an address is kept in the browser session behind a short `state_key`, the same way other pages already hand long searches over, so Back and reload still work there, but that address can't be shared. While a smart list is loaded its id stays in the address, so saving after Back or a reload still updates that list. The Featured Rail editor's address doesn't change.
- The **Refresh Colorscapes** card in Admin > Tasks is now **Regenerate Thumbnails**, with two buttons. **Changed only** does what the old button did: it rebuilds thumbnails and cover colors for comics marked as changed by a scan or the cover audit's `--mark-thumbnails`. **All** rebuilds every comic in every library, after a confirmation. Neither rescans files. The endpoint keeps its path (`POST /api/tasks/refresh-colorscapes`) and takes a new `force` option.

## Fixed

- Fixed the search index migration tests breaking whenever a column is added to comics. They seeded comics through the ORM model into databases at older revisions, so the insert named columns those revisions don't have. They now insert only the columns they need.
- Fixed the Refresh Colorscapes card saying it "only processes comics that are missing color data". It actually rebuilt thumbnails and colors for comics marked as changed. The renamed card now says so.
- Fixed the reader's Fullscreen and Keyboard Shortcuts buttons disappearing on every touchscreen, including tablets, with no other way to reach them ([#164](https://github.com/breenyoung/ComicServer/issues/164)). Both now show on touch devices, and the phone-width "⋯" menu has entries for them. Fullscreen is hidden only where the browser can't go fullscreen, such as iPhone Safari. The magnifier stays hidden on touch devices, because it follows a hovering mouse and doesn't respond to touch.
- Fixed navbar quick search needing words in the exact order and punctuation of the name, so "brother lono 100 bullets" didn't find "100 Bullets: Brother Lono" and "sam wilson captain america" didn't find "Captain America: Sam Wilson". It now finds names containing every typed word, in any order, ignoring punctuation. This applies to every group: series, collections, reading lists, people, characters, teams, locations and pull lists.
