# Parker 0.1.29 Release Notes

Status: Unreleased

`0.1.29` begins with Home page personalization and includes security hardening for authentication secrets and authenticated media access.

## Added

- Added account-scoped Home rail layout preferences so users can reorder or hide top-level Home rails.
- Added Home layout API endpoints for reading, saving, and resetting a user's rail layout.
- Added a Home customization modal with drag reordering, move buttons, visibility toggles, Hide All, Show All, and Reset to Default actions.
- Added a recoverable no-visible-rails fallback with Customize and Reset actions.
- Added an Alembic migration for the nullable `users.home_rail_layout` JSON preference.
- Added comic summaries to reading-list detail rows, clamped to keep long descriptions tidy.
- Added API and browser coverage for default layout resolution, per-user persistence, missing rail insertion, unknown key rejection, reset behavior, reorder persistence, hidden rail fetch suppression, and all-hidden recovery.
- Added startup validation requiring `SECRET_KEY` to be explicitly set to a non-placeholder value.
- Added a migration that moves existing `random_covers` login background settings to `cycling_static_covers`.
- Added regression coverage for secret-key validation and authenticated media endpoints.

## Changed

- Home now renders rails from the resolved user layout while preserving the previous default rail order for users who have not customized Home.
- Hidden Home rails are no longer fetched by the browser.
- New built-in Home rails are inserted as visible during layout resolution without mutating saved layouts on read.
- Comic, series, and volume detail breadcrumbs are slightly larger on medium and larger screens, with more forgiving link targets.
- Series detail now groups admin-only controls in a labeled Admin pill.
- Docker Compose and setup documentation now require operators to provide a unique `SECRET_KEY`.
- Login backgrounds now default to bundled static cover cycling instead of random covers from the server's library.
- The admin settings UI no longer offers random library covers as a login background option.

## Fixed

- Fixed insecure placeholder JWT secrets being accepted at startup.
- Fixed comic page, thumbnail, random-background, and OPDS thumbnail endpoints so media access requires authentication and respects library and age-rating access.
- Fixed debug configuration output so `SECRET_KEY` is redacted.
