# Parker 0.1.30 Release Notes

Status: Unreleased

`0.1.30` hardens first-run administrator bootstrap so new installs no longer start with a shared default admin password.

## Added

- Added `INITIAL_ADMIN_PASSWORD` bootstrap support for creating the first administrator when no active superuser exists.
- Added optional `INITIAL_ADMIN_USERNAME`, defaulting to `admin`, for first administrator creation.
- Added an admin-only warning when Parker detects that the `admin` account still accepts the legacy `admin` password.
- Added privacy-safe recent scan job health to startup diagnostics without exposing library names, paths, filenames, IDs, or raw job errors.
- Added some new static cover choices

## Changed

- Fresh databases no longer receive the legacy `admin` / `admin` account from the historical Alembic seed migration.
- Docker, `.env`, README, and Quickstart documentation now describe the first-admin bootstrap variables.
- Startup diagnostics now redact local paths by default, while admins can reveal full paths on the diagnostics page when actively troubleshooting.
- Support snapshots now use redacted database, library-root, and comics-probe paths by default.
- Top navigation now always uses Parker branding, while the configured server display name remains visible on the login and About pages.
- Admin settings now shows a temporary cover preview when choosing a static login background cover.
- Login static-cover cycling now shuffles the bundled cover deck once per page load before cycling, so the first displayed cover varies without repeating covers within the deck.

## Fixed

- Prevented first-run bootstrap from mutating or locking out existing administrator accounts during upgrades.
- Renamed some static cover labels for more sensible ordering in the dropdown.
- Fixed Related tab collection and reading-list cards on series detail pages showing `0 comics` by including visible comic counts in the series detail payload.
