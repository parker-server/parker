# Parker 0.1.48 Release Notes

Status: Draft

## Added

- Added notifications. A bell in the top bar shows how many notifications are unread and opens a list of the latest ones; clicking one marks it read and opens what it is about. A Notifications page (`/user/notifications`) lists them all, with All and Unread tabs, Mark all read, remove, and Clear read. Each user can turn kinds of notification on or off in Account Settings, and admins can turn the whole feature off with **Enable Notifications** under the new Settings → Features section. Read notifications are deleted after 30 days (**Read Notification Retention** under Settings → System) and unread ones after 90 days, checked once a day.
- Added notifications for new issues in followed volumes. After a library scan, each follower gets one notification per volume, such as "3 new issues in Saga Vol 1", linking to the volume. Later scans add to the same notification until it is read. Followers only hear about comics they can see, by library and age rating. A library's first scan, and any scan that adds more than 500 issues to followed volumes, is treated as a bulk import and notifies nobody.
- Added a Year in Review notification. From December 15, users who finished at least one comic that year are told their Year in Review is ready, once per year. If the server is off in late December, a check in January still sends it for the year just ended.
- Added What's New. After Parker is updated, each user gets one notification about new features, linking to a What's New page (`/whats-new`, also linked from Admin → About) that lists reader-facing highlights by version. Admins also see admin-only highlights. A fresh install announces nothing; a server that already has libraries announces this version's highlights the first time it starts.
- Added user selection to the Kavita migration. The preview now lists every Kavita user, not just the first 25, showing whether they are new or already in Parker, whether they are a Kavita admin, and how many of their progress records can be imported. Admins tick the users to bring over (all are ticked by default, with Select all and Select none), and only those users, their library access and their reading progress are imported. Start Migration stays disabled until at least one user is ticked.

## Changed

- Character and team timelines load faster. They look up the subject's issues directly instead of checking every comic for the name, and character and team links now have indexes for that lookup. On a 73,000-issue library, a timeline for a character in 250 issues went from about 0.06 seconds to 0.012, Wolverine (3,944 issues) from 0.27 to 0.18, and Batman (7,162 issues) from 0.48 to 0.36.
- Timeline search suggestions are much faster on libraries with statistics: on the same library, typing "w" went from 0.14 seconds to 0.001, and "spider" from 0.08 to 0.009.

## Fixed

- Fixed timelines holding up the rest of the server while they load. The timeline and timeline suggestion endpoints ran their database work inside `async` routes, so other requests waited until they finished. They are plain `def` routes now.
- Fixed a timeline's reading-list and collection lookups slowing down once database statistics existed. SQLite checked every reading list against each of the timeline's issues one at a time; Batman's took 83ms instead of 7ms. They now read the items once and filter them.
- Fixed the Kavita migration preview showing a server error with a raw SQLite message, such as "no such table: Chapter", when the uploaded file isn't a Kavita database. Text files, images, empty files, other SQLite databases and databases missing Kavita tables now get a clear message telling the admin to upload the kavita.db file from their Kavita config folder.
